## 二、还没有的功能（待开发清单）

### P1 — 直接对应雏形核心设想
1. **同平台多账号池与账号级轮换**
   现状：relay_order 只在 5 个平台之间换，一个平台额度尽只能换别家。
   目标：`platforms.deepseek.accounts: [工作号, 备用号]`，每账号独立 profile 与冷却；
   接力优先在同平台换账号，再跨平台。需要：账号注册表、profile 命名 `profiles/<平台>/<账号>`、
   `switch_account` 编排、冷却按账号记录。
2. **平台侧会话发现（list_conversations）**
   现状：只能回到本工程自己记录的 chat_ref。
   目标：每平台适配器实现 `list_chats()`（从侧边栏 DOM 解析历史会话标题+链接），
   控制台可选“从平台历史恢复”，MCP 侧以只读、需批准的方式暴露摘要预览。
3. **MCP 会话状态工具（雏形的 `get_account_status`）**
   现状：Agent 只能看到对抗池。
   目标：新增 `get_session_status(session_id, reason)` 只读工具——返回平台接力链、
   各平台冷却状态、摘要预览（前 N 字）。内容经对抗池授权机制逐次批准，不破坏隔离设计。

### P2 — 体验补全
4. **Ghost messages 内联展示**
   交接时把最近几轮原文以引用块样式附在交接包里（现在只有纯文本拼接），
   让新会话“看起来连续”；纯前端拼接，改动只在 `_deliver_handoff`。
5. **limit_texts 多语言扩展**
   DeepSeek/Kimi/豆包补英文界面文案（网页切英文时检测失效）；probe.py 增加
   “用英文界面再探测一遍”的提示。
6. **截断回复的接力策略开关**
   现状：回复被截断（finished=False）只在 DOM/429 也报警时才接力。
   目标：`relay_on_truncation: true` 时截断也触发接力（长文场景）。

### P3 — 明确不做（记录原因，防止回头再加）
7. **浏览器指纹伪装 / 反检测** —— 违反平台使用条款，且与“本人账号”设计矛盾。
8. **凭据（密码）代填** —— 引入明文凭据即破坏“Agent 零明文”底线，保持手动登录。

## 三、与雏形的两处有意分歧（设计决定，非遗漏）

1. **MCP 不是控制平面，而是最小授权通道。** 雏形设想 MCP 暴露 `switch_account` 等
   编排工具直接驱动浏览器；工程改为：浏览器只受控制台驱动，Agent 只经对抗池
   读写，每次读取都要人批准。若 Agent 本身可信度不足，这比雏形更安全。
2. **不管理账号密码。** 雏形参考 psamvault / moonlighting 做“凭据 broker 注入”；
   工程选择根本不碰密码（手动登录 + 持久 profile），凭据面为零，broker 层可省。
